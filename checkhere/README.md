# HINT 체크히어 검수 v0.2 · 지정 관리자 수정

반·날짜별 실제 입퇴실, 입실·교시 및 퇴실 관리자 메모, 외출 구간을 읽어 검토하고, 수정 근거와 변경 전후를 확인한 뒤 체크히어에 반영하는 Windows·macOS 로컬 연결 프로그램입니다. AI API를 호출하지 않습니다.

## Windows에서 실행

1. `체크히어 시작.cmd`를 더블클릭합니다. 크롬에서 `http://127.0.0.1:8765`가 열립니다.
2. **체크히어 로그인**을 누르고 새 전용 크롬 창에서 로그인합니다. 기존 크롬 로그인 정보를 복사하지 않습니다.
3. 반과 날짜를 선택하고 **체크히어에서 수집**을 누릅니다. 기간은 최대 31일이며 현재 UI는 평일 강의를 대상으로 합니다.
4. 수정은 **운영 포털 → 체크히어 → 검토·수정**에서 지정 계정으로 로그인하여 처리합니다. 다른 관리자는 수집·조회만 가능합니다. 독립 실행 화면에서는 직접 수정하지 않습니다. 시간 공란으로 지우기와 삭제는 지원하지 않습니다.
5. 결과가 `검증 완료`인지 확인합니다. `일부 실패`, `충돌`, `결과 미확인`이면 재수집 후 실제 값을 확인합니다. 불확실한 저장을 자동 재시도하지 않습니다.

이 개발 PC에서는 Codex에 포함된 Node와 Playwright를 자동으로 찾습니다. 배포용 Windows 묶음은 Node와 Playwright를 함께 포함하고, PC에 Chrome이 설치되어 있어야 합니다. 다른 PC에서 소스만 실행하려면 Node 24 이상과 이 폴더의 `npm install`이 필요합니다.

## macOS에서 실행

1. Google Chrome과 Node.js 24 이상을 준비합니다. `체크히어 시작.command`는 프로젝트의 `runtime/node`, Codex 런타임, Homebrew, Volta, asdf, mise 및 일반 PATH 순서로 Node를 찾습니다.
2. `체크히어 시작.command`를 더블클릭합니다. Git clone으로 받은 파일은 실행 권한이 유지됩니다. ZIP 등으로 받아 실행 권한이 사라진 경우 터미널에서 `chmod +x "체크히어 시작.command"`를 한 번 실행합니다.
3. 첫 실행에서 Playwright가 없으면 같은 폴더의 `package.json`을 기준으로 npm 의존성을 자동 설치합니다. Playwright 자체 Chromium은 받지 않고 설치된 Google Chrome을 사용합니다.
4. `http://127.0.0.1:8765`가 Chrome에서 자동으로 열립니다. **체크히어 로그인**을 누르고 새 전용 Chrome 창에서 로그인합니다. macOS에서도 `data/chrome-profile`에 전용 로그인 세션이 유지됩니다.
5. 운영 포털의 **체크히어** 탭에서 로컬 화면의 연결 키를 입력하고 수집합니다. 브라우저가 로컬 네트워크 접근을 묻는 경우 허용해야 합니다.
6. 이후 수집·검토·지정 관리자 수정·Firebase 보관 흐름은 Windows와 동일합니다. Windows의 `Start.ps1` 및 `.cmd` 파일은 그대로 유지됩니다.

> macOS 실행기는 Apple Silicon과 Intel Mac의 일반적인 Homebrew 경로를 모두 확인합니다. 실제 체크히어 화면 DOM과 로그인 정책은 Windows와 동일한 Playwright 수집기를 사용하므로, 최초 배포 후 실제 Mac에서 로그인 → 1개 반·1개 날짜 수집 → 읽기 전용 검수까지 먼저 확인한 뒤 수정 기능을 사용하는 것을 권장합니다.

## 플랫폼 연결

관리자 **체크히어** 탭에서 넓은 검수 화면을 바로 엽니다. 윈도우 연결 프로그램 설정에 이 PC 화면의 연결 키를 입력합니다. 브라우저에서 로컬 네트워크 접근을 묻는 경우 해당 연결을 허용해야 합니다. 키는 플랫폼 화면 메모리에만 보관하며 서버를 재시작하면 바뀝니다.

플랫폼에서 수집하면 결과를 `classes/{반}/checkhereSnapshots/{작업ID_날짜}`에 자동 보관합니다. 별도 ‘플랫폼에 저장’ 버튼으로 다시 저장할 수 있습니다. 플랫폼 보관에 실패해도 로컬 수집 성공과 구분해 안내합니다. 연결 프로그램 없이도 플랫폼의 과거 저장본은 조회할 수 있습니다.

현재 독립 실행 화면은 PC에만 저장합니다. 서버 자동 보관은 플랫폼 화면을 열고 연결한 상태에서 동작하며, 화면을 닫은 뒤에도 실행되는 예약 수집·백그라운드 업로드는 아직 구현하지 않았습니다. 다른 PC의 관리자는 플랫폼 보관본을 조회할 수 있습니다.

## 현재 수정 흐름과 보존된 요청 기능

- 현재 요청·승인 목록과 담임 요청 화면은 숨김 상태입니다. 구현과 기존 기록은 보존하며 `index.html`의 `CHECKHERE_REQUESTS_VISIBLE`로 노출을 제어합니다.
- **hint.kpc@gmail.com의 인증된 Google 로그인**만 학생별 ‘검토·수정’을 사용할 수 있습니다. 다른 관리자는 수집·조회·플랫폼 보관 및 내려받기만 가능합니다.
- 지정 계정은 수정 근거와 변경 전후를 확인한 뒤 ‘체크히어에 반영’을 누릅니다. 별도 승인 목록을 거치지 않습니다.
- 내부에서는 기존 `checkhereRequests`의 변경 전후 기록과 승인 검증을 재사용합니다. 서버는 지정 계정의 ID 토큰과 승인 문서를 검증하므로 버튼만 우회해도 다른 계정은 수정할 수 없습니다.
- 수정 전 원본 버전 확인, 중복 반영 방지, 저장 후 재조회 검증은 유지합니다. 응답이 끊기면 같은 창의 동일 변경은 기존 처리 상태를 확인하며 새 쓰기를 반복하지 않습니다.
- 결과 미확인·부분 실패는 재수집해서 확인합니다. 요청 목록을 다시 노출하면 기존 ‘반영 결과 확인’도 사용할 수 있습니다.
- 연결 프로그램 build `20260910.5` 이상이 필요합니다. 이번 화면 개편은 서버 프로토콜을 유지하므로 이미 해당 버전을 실행 중이면 재시작할 필요가 없습니다.

**플랫폼 배포에는 웹 파일과 변경된 `firestore.rules`를 함께 검토·적용해야 합니다.** 기존 운영 데이터나 권한 규칙은 이 프로그램 실행만으로 변경되지 않습니다. 새 보관 경로는 기존 관리자만 읽고 생성할 수 있으며 수정·삭제는 거부합니다. 배포 전 실제 관리자 인증 및 저장 권한 확인이 필요합니다.

## 판단 범위

- Workpack 1.2.1과 제공된 출결 규정의 09:00–18:00, 점심 12:00–13:00, 입실 10분·퇴실 10분 유예를 적용합니다.
- 09:10의 초 단위 경계는 매뉴얼에 명확한 기준이 없어 확인 대상으로 남깁니다.
- 실제 참여시간은 강의시간 밖과 점심, 겹치는 외출 구간을 제외해 계산합니다. 화면의 실제 참여시간은 최종 인정 교육시간과 구분합니다. 50% 근처의 유예·인정 시간 적용은 검토가 필요합니다.
- 인정출석은 시간만으로 확정하지 않습니다. 인지한 과거 시트 값은 ‘과거 시트’로 표시합니다. 현재 버전은 실시간 Google Sheet·수기·인정서류 수집을 추가하지 않습니다.
- 중복 출결, 사용자 정상 확인 후 반영 제외된 기록, 다른 강의시간, 입실과 교시 시간이 다른 기록은 자동 반영하지 않습니다.
- 실제 입실과 교시 기록을 각각 보관합니다. 오늘 수업이 끝나기 전 퇴실·교시 기록이 비어 있는 경우는 ‘진행중’으로 구분합니다. 지난 날짜의 두 시간이 다르면 수집 실패가 아니라 기록 불일치로 표시하고 반영을 제한합니다.
- 확인된 결석의 공란을 정상으로 유지하며, 출결 시간 공란만으로 무단결석이라 확정하지 않습니다.
- 현재 실제 사이트에서 확인한 단일 교시 표에 대응합니다. 다중 교시·화면 구조 변경 시 실패로 표시합니다. 17개 반 메뉴와 페이지 탐색을 구현했으며, 모든 반의 실제 구조 검증은 별도 수행해야 합니다.

## 기록 보존과 검증

`data/attendance.sqlite`에 수집 원본을 추가 저장하고, 수정 전후 및 저장 확인 과정을 기록합니다. `data/chrome-profile`에는 이 전용 크롬의 로그인 세션이 남습니다. 두 폴더 모두 Git 및 배포 묶음에서 제외합니다. 출결 원본이나 사용자 파일을 삭제하는 기능은 없습니다. 수집 실패를 빈 메모로 바꾸지 않습니다.

쓰기 직전 이름과 식별정보, 시간·메모·외출 구간을 다시 대조합니다. 입실·퇴실 저장은 각각 별개 작업이므로 부분 성공이 가능합니다. 각 저장 후 화면을 다시 열고 값을 읽어야만 검증 완료가 됩니다. 다른 관리자의 변경이 발견되면 중단합니다. 동일한 요청 식별자는 한 번만 처리합니다.

## 개발 및 시험

```text
node server.mjs
node --test tests/*.test.mjs
```

시간 경계, 점심·외출 중복, 인정출석 구분, 메모 누락·불일치, 동일 이름 식별, 저장 직전 충돌, 부분 성공, 응답 끊김 후 재조회, 중복 요청, 로컬 API 접근 제한과 실제 DOM 형태의 가상 수정 창을 시험합니다. 테스트는 가상 학생을 사용하며 체크히어 운영 출결을 바꾸지 않습니다.

기존 실제 날짜·반 수집과 사유 수정은 사용자가 확인했습니다. 승인 기능은 가상 학생으로 요청 작성, 지정 관리자 제한, 변경 전후 표시, 저장 실패, 요청 위변조·중복 실행 방지와 토큰 검증을 시험합니다. 실제 학생의 출결을 변경하는 시험은 수행하지 않습니다. 운영 배포 및 실제 로그인 검증 결과는 별도 보고합니다.

기술 근거: [Playwright 브라우저 프로필](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context), [인증 세션](https://playwright.dev/docs/auth). 외부 API 제공 여부는 확인되지 않아 공개 화면의 표와 수정 창을 사용합니다.
