### 먼저 확인 (되돌릴 수 있는지) — 통과
- 같은 날 순번 4(입실·퇴실 모두 '-')의 퇴실 칸을 누르자 「퇴실 시간 수정」 창이 열림 — `followup-cap1-빈퇴실칸-수정창.jpg`
- 창 안의 값

### 삭제 시험
1. 대상 학생의 퇴실 칸 → 「퇴실 시간 수정」 창. 프로그램으로 표의 같은 행 학생과 같은지 확인함. 기존 시간 17:50:08, 메모 빈칸
2. **`삭제`를 한 번 누름**
   - **확인창이 뜨지 않음**. 브라우저 confirm/alert 호출도 없고, 화면 안 확인창이나 토스트도 없음
   - **한 번에 지워지고** 수정창이 바로 닫힘. 두 번 누를 필요 없었음
3. 삭제 뒤 표(허용 시간 기반) — `followup-cap2-삭제후.jpg`
   - 입실: 08:55:31 그대로
   - **1교시(09:00~18:00) 칸: 08:55:31 → `-`** (퇴실만 지웠는데 1교시도 비워짐)
   - **퇴실 칸: `-`**
   - **총 강의 참여 시간: 9시간 0분 → `-`**
   - 외출: 0분(-) 그대로
4. 삭제 때 나간 요청
   - `DELETE` `checkhere-admin-api.ihereapp.com/api/v3/history/event/delete` → **200**
   - 앞뒤 요청
     - 앞: `GET check.ihereapp.com/api/auth/session` 200
     - 뒤: `GET …/api/v3/history/attendee/detail/academy/{academyId}/schedule/{scheduleId}/type/STUDENT/isRealTime/false` 200(표 다시 읽기)
   - 방식(DELETE)은 화면이 쓰는 체크히어 코드에서 확인함: `{path:"history/event/delete",method:"DELETE",body:e}`
     - Cowork 브라우저 도구의 Network 기록에는 이 요청이 잡히지 않음
     - 브라우저 성능 기록(Resource Timing)으로 주소 경로·fetch·200만 확인
     - 요청 본문·토큰·쿠키·헤더는 보지도 적지도 않음
5. **바로 되돌림**: 같은 퇴실 칸 → 수정창(기존 시간 `-`, 삭제 버튼 없음) → 수정 시간 `17:50:08` 입력, 관리자 메모 빈칸 → `변경`

   - 퇴실 칸 ⓘ(메모) 아이콘 없음. 수정창을 다시 열어 기존 시간 17:50:08, 관리자 메모 빈칸을 확인함

### collector.mjs `write`에 주는 참고
- 시간 지우기
  1. 수정창에서 `getByRole('button',{name:'삭제',exact:true})`를 한 번 누름
  2. 확인창 처리는 필요 없음
