# Cowork 작업 요청 — 체크히어 개인정보 가림(마스킹) 확인 (2026-10-15)

체크히어 출결상세가 이제 개인정보를 가려서 보여 줍니다.
- 성명: 첫 글자 + `**` (예: `가**`)
- 전화번호: `010-****-0000` (끝 4자리만 보임)
- 메모(학번/사번): `**************`
- `개인정보 마스킹 해제`를 누르고 메일로 받은 인증번호를 넣으면 10분 동안 원문이 보임. 연장은 2번까지

연결 프로그램(`checkhere/collector.mjs`)은 표의 이름과 전화번호 전체로 학생을 찾습니다.
그래서 가린 화면에서는 수집·반영·삭제가 모두 멈춥니다. 다른 학생에게 잘못 쓰지는 않습니다.
다만 중계가 켜져 있으면 대기 중인 수정 요청이 약 5분(5번 실패) 뒤 자동 반려됩니다.
Claude Code는 체크히어를 볼 수 없습니다. 가린 화면에서 무엇이 가려지고 무엇이 남는지 Cowork가 확인해 주세요.
이 결과로 '가린 화면에서도 같은 학생을 확실히 찾는 방법'을 정합니다.

결과 파일은 **Google Drive 폴더 `HINT Claude Code 전달`**에 `checkhere-masking-report.md` 한 파일로 올립니다.

## 꼭 지킬 것 (하지 않는 일)

1. 인증번호는 **사용자가 직접** 받고 직접 넣는다. Cowork는 메일함을 열지 않는다. 인증번호를 읽거나 입력하지 않는다.
2. 가림을 코드로 풀거나 건너뛰지 않는다.
   - 콘솔에 코드 붙여 넣기, fetch 감싸기, 확장 프로그램, 체크히어 주소 직접 부르기 모두 하지 않는다
   - 개발자 도구는 **Network·Elements·Sources 탭을 보기만** 한다
3. 체크히어 출결은 **바꾸지 않는다.**
   - `변경`·`삭제`·`저장`·`정상처리`·`적용` 버튼을 누르지 않는다
   - 수정창의 `삭제`는 **확인창 없이 바로 지운다**(10/14 확인). 수정창·정상처리 창이 열려 있을 때는 키보드(Enter 포함)를 쓰지 않는다
   - 창은 `취소`나 X로 닫는다
   - 「강의시간 출석 정상처리」 창의 학생 체크박스도 누르지 않는다
4. 보고서에 실제 값을 적지 않는다.
   - 이름, 전화번호(끝 4자리 포함), 학번, 관리자 메모 글, 담임 이름, id 값(attendeeId·userId·eventId) 모두 적지 않는다
   - `원문`/`가림`/`있음`/`없음`/`같음`/`다름`과 항목 이름만 쓴다
   - 예시가 꼭 필요하면 `가상학생`·`0000`을 쓴다
5. 캡처는 **가린 상태 화면만** 찍는다. 끝 4자리까지 덮은 뒤 찍는다. 원문 표시 중인 화면은 캡처하지 않는다.
   - Cowork는 화면을 찍어서 보므로, 원문 표시 중에는 아래 2번에 적힌 것만 보고 바로 `종료`한다
   - 사용자가 원하면 2의 3·4번(원문/가림 판단)은 사용자가 직접 보고 Cowork에게 `원문`/`가림`만 알려 준다
6. Network 응답을 복사(Copy response)하지 않는다. HAR 파일로 저장하지 않는다. 실제 값이 그대로 들어 있다.
   - 끝나면 Network 기록을 지우고(Clear 버튼) 개발자 도구를 닫는다
7. 확인은 **평소 쓰는 크롬**에서 한다. 수집 PC 연결 프로그램의 **전용 크롬은 건드리지 않는다**(해제·새로고침·클릭 모두 하지 않음).
   - 평소 크롬이 체크히어에 로그인되어 있지 않으면 로그인은 사용자가 한다. Cowork는 비밀번호를 넣지 않는다
   - 사용자가 새로 로그인했다면, 그 뒤 연결 프로그램 화면이 '로그인 필요'로 바뀌는지 본다(한 계정이 한 곳에서만 로그인되는지)
8. `checkhere/data/`는 열지 않고 어디에도 올리지 않는다. 저장소 커밋·push는 하지 않는다.
9. 원문 표시 중에는 자리를 비우지 않는다. 확인이 끝나면 바로 `종료`를 누른다.

## 0. 연결 프로그램이 지금 멈췄는지 (보기만)

1. 수집 PC의 연결 프로그램 화면(`http://127.0.0.1:8765`)에서 최근 작업 5개의 상태와 메시지를 본다.
   - `학생 식별을 위해 전화번호 표시가 필요합니다.`가 있는지
   - 있으면 처음 나온 시각
2. 실시간 베타 중계 탭(`/checkhere-live.html`)의 오늘 기록에서 두 가지 개수만 센다.
   - `갱신 실패` 줄 수
   - `자동 반영을 5번 시도했지만` 반려 건수
   - 학생 이름은 적지 않는다
3. 전용 크롬 화면이 지금 가림 상태로 보이는지 화면만 본다(새로고침·클릭 없이).
4. 1의 오류가 있거나 3에서 가림으로 보이면 **사용자에게 바로 알리고 `중계 멈춤`을 권한다.**
   - 중계가 돌면 10분마다 17반 갱신이 모두 실패하고, 대기 중 요청은 5번 실패 뒤 반려된다
   - `중계 멈춤`은 사용자가 정해서 누른다. Cowork가 혼자 판단해 누르지 않는다
   - 반려가 이미 있으면 건수만 알린다

## 1. 가린 상태에서 확인 (평소 크롬)

대상: 아무 반 하나, 지난 교육일 하나(예: 어제). 관리자 메모·외출이 있는 학생이 있는 날이면 더 좋다.
경로: 출결 관리 > 강의 출석 조회 > 반 `보기` > 날짜 `보기` = 출결상세.

1. F12 → Network 탭. `Preserve log`를 켜고 필터는 `Fetch/XHR`. 그다음 출결상세를 새로고침한다.
2. 나간 요청 주소를 모두 적는다.
   - id·날짜는 `{id}`·`{date}`로 바꿔 적는다
   - 예: `GET …/history/attendee/detail/academy/{id}/schedule/{id}/type/STUDENT/isRealTime/false`
   - 요청마다 응답(Preview)에 이름·전화번호 항목이 있는지, 있으면 `원문`/`가림`
     (특히 `history/attend/detail/lecture`·`history/attend/times`)
3. 표시 방식에서 `실제 시간 기반`을 누른다. 새로 나간 요청을 적는다. 특히 `isRealTime/true` 요청이 나가는지.
4. `history/attendee/detail` 요청 → Preview 탭 → `data.eventResultList[0]`만 펼친다.
   아래 항목마다 `원문`/`가림`/`없음`을 적는다.
   - `name`, `userName`, `phone`, `identifier`
   - `attendeeId`, `sequence`
   - `eventList[0].userId`, `eventList[0].eventId`
   - 가림이면 모양만 적는다(예: `첫 글자+**`, `010-****-끝4자리`, `*만`)
   - 10/14 보고서(`2026-10-14-checkhere-api.md`)에 없던 새 항목 이름이 있으면 이름만 적는다
   - `isRealTime/true`와 `isRealTime/false` 응답 둘 다 본다. 두 응답의 `attendeeId`가 같은지(`같음`/`다름`)
   - 관리자 메모가 있는 학생을 하나 더 펼쳐 `eventList[].memoByAdmin`이 `원문`/`가림`/`일부 가림`(예: 메모 안 담임 이름만 `*`)인지 본다. 글은 적지 않는다
5. 표의 `순번`과 JSON `sequence`가 같은 학생을 가리키는지 3명만 본다(첫 행, 가운데 행, 마지막 행).
   - 표의 가린 이름 첫 글자·끝 4자리와 같은 sequence의 JSON 값이 맞으면 `같음`
   - 순번에 빠진 번호가 있는지(예: 1·2·4), 표의 행 순서와 JSON 목록 순서가 같은지
6. 화면 구조가 그대로인지 본다.
   - 학생 명단 표의 머리글을 **왼쪽부터 모두** 적는다(체크박스 칸이 새로 생겼는지 포함). `성명`·`전화번호`가 여전히 있는지
   - 출결상세의 표가 여전히 2개(학생 명단 표 + 시간 표)인지
   - 가림 안내와 해제 버튼이 표 안에 있는지, 표 밖에 있는지
   - 화면 위 제목 줄(`[N반] … (담임) | … 출석부` 모양)의 **담임 이름**이 `원문`/`가림`인지
   - 강의 출석 조회 목록의 반 이름(`[N반]`)·날짜·담임 이름이 그대로인지
7. 이름 가림 모양을 본다.
   - 두 글자·세 글자·네 글자 이름이 있으면 `*` 개수가 늘 2개인지, 글자 수에 따라 다른지
   - 첫 글자 말고도 보이는 글자가 있는 이름이 있는지(두 글자 성, 영문 이름, 띄어쓰기 있는 이름). 있으면 모양만(예: `가가*`, `A*** B***`)
   - 첫 글자가 같고 끝 4자리도 같은 학생이 이 반에 있는지(`있음`/`없음`만)
8. **id가 날짜마다 같은지** 본다.
   - 같은 반의 다른 날짜(예: 그제) 출결상세를 연다
   - 표에서 같은 학생 2명을 고른다(가린 이름 첫 글자 + 끝 4자리로 찾음)
   - 두 날짜의 `attendeeId`와 `eventList[0].userId`가 같은지 `같음`/`다름`만 적는다
   - 값은 적지 않는다. 눈으로 앞 8자리만 비교하면 된다
   - 출결 기록이 하나도 없는 학생(`eventList`가 빈 학생)이 있으면, 그 학생에게도 `attendeeId`가 있는지
9. 수정창을 본다. 기록이 있는 학생 한 명을 고른다(관리자 메모가 있는 학생이면 더 좋다).
   - `1교시` 칸을 눌러 「1교시 시간 수정」 창을 연다. 이때 브라우저 기본 알림창(회색 작은 창)이 뜨는지
   - 이름 칸(`#name`)에 보이는 값이 `원문`/`가림`인지
   - 메모 칸(`#memoByAdmin`)에 기존 관리자 메모가 있으면 `원문`/`가림`/`일부 가림`인지. 메모 칸은 누르지 않는다
   - 창 안에 전화번호가 보이는지
   - `변경`·`삭제` 버튼이 보이고 회색(비활성)이 아닌지 Elements에서 `disabled`만 본다. **누르지 않고 마우스도 올리지 않는다.** `취소`로 닫는다
   - 수정창을 열 때 새 요청이 나가는지(주소 모양만)
   - `퇴실` 칸도 같은 방법으로 본다
10. 외출이 있는 학생이 있으면 외출 칸을 누른다. 창 제목(「○○ 님의 외출 시간 확인」)의 이름이 `원문`/`가림`인지 본다. 닫는다.
11. 「강의시간 출석 정상처리」 창을 연다.
    - 학생 목록의 이름·전화번호가 `원문`/`가림`인지
    - 순번이나 끝 4자리처럼 학생을 구분할 정보가 보이는지
    - 창을 열 때 미리 체크된 학생이 있는지
    - 체크박스는 누르지 않는다. 키보드도 쓰지 않는다. `취소`로 닫는다
12. (할 수 있으면) Sources에서 화면이 이미 받아 둔 JS를 본다.
    - 수정창의 `history/event/update`·`history/event/delete` 본문이 10/14 보고서와 같은지(`attendeeId` 사용 등)
    - 가린 상태에서도 그 본문이 바뀌지 않는지
    - 실제 요청은 보내지 않는다. 그래서 '가린 상태에서 변경·삭제가 실제로 되는지'는 버튼 상태와 코드로만 판단한다
13. 체크히어 설정·계정 메뉴에 아래 같은 메뉴가 있는지 본다. 있으면 메뉴 이름만 적고 바꾸지 않는다.
    - 마스킹 끄기, 권한별 원문 보기, 외부 연동·API

## 2. 해제 상태에서 확인 (인증번호는 사용자가 입력)

1. 사용자에게 알린다. 사용자가 `개인정보 마스킹 해제` → 메일 인증번호 입력을 **직접** 한다.
   - Cowork는 버튼 위치, 창 문구(인증번호 자리 수, 유효 시간 안내)만 적는다
   - 해제 창이 화면 안의 창인지, 브라우저 기본 알림창(alert·confirm·prompt, 회색 작은 창)인지
   - 메일 주소는 적지 않는다. 메일이 오기까지 걸린 시간만 적는다
   - 인증번호 메일이 연결 프로그램이 쓰는 체크히어 계정의 메일로 가는지 사용자에게 묻는다(`같음`/`다름`/`모름`만)
2. 해제 직후 Network에 새로 나간 요청 주소를 적는다.
   - 해제 요청 주소 모양
   - 출결상세를 다시 받는지. 같은 `history/attendee/detail` 주소인지, 다른 주소인지
   - 새 요청 없이 표가 바로 원문으로 바뀌면 `요청 없음`으로 적는다(원문이 이미 화면에 와 있었다는 뜻이라 중요)
3. 1의 4번 항목을 다시 본다(`원문`/`가림`). `attendeeId`·`userId`가 해제 전과 `같음`/`다름`.
4. 수정창 `#name`·`#memoByAdmin`, 외출 창 제목, 정상처리 창 목록, 제목 줄 담임 이름을 다시 본다(`원문`/`가림`). 아무것도 누르지 않는다.
5. 해제가 어디까지 유지되는지 본다. 각각 `유지` 또는 `가림으로 돌아감`.
   - 같은 화면 새로고침(F5)
   - 같은 반 다른 날짜
   - 다른 반
   - 같은 크롬의 새 탭에서 출결상세 열기
6. 타이머를 본다.
   - 남은 시간 표시 모양
   - `연장`을 1번 누르면 남은 시간이 몇 분이 되는지, 남은 연장 횟수가 어떻게 보이는지
   - 시간이 끝나면 새로고침 없이 화면이 가림으로 바뀌는지. 그때 새 요청이 나가는지
   - 연장·종료·시간 끝 때 브라우저 기본 알림창이 뜨는지. 뜨면 문구 모양만 적는다
   - 연장을 다 쓰지 않아도 되면 `연장`은 1번만 눌러 본다
7. (사용자가 원할 때만) 해제가 계정 전체에 걸리는지 본다.
   - 중계는 0번에서 멈춘 상태로 둔다. 이 확인을 위해 중계를 켜 두지 않는다(대기 중 요청이 반려됨)
   - 해제 중에 **사용자가** 연결 프로그램 화면에서 반 하나·오늘 날짜만 `수집`을 누른다(체크히어는 읽기만 함)
   - 성공하면 '해제는 계정 전체에 걸림', `전화번호 표시가 필요합니다`로 실패하면 '해제는 그 브라우저에만 걸림'
8. 끝나면 `종료`를 누른다. 화면이 가림으로 돌아왔는지 본다. Network 기록을 지우고 개발자 도구를 닫는다.

```
## 0. 연결 프로그램 상태
- '전화번호 표시가 필요합니다' 오류: 있음/없음 (처음 시각: …)
- 오늘 '갱신 실패' 줄 수: … / '5번 시도' 반려: …건
- 중계 멈춤: 누름(사용자 지시)/안 누름
- 전용 크롬 화면: 가림/원문
- 평소 크롬 새 로그인 뒤 연결 프로그램 '로그인 필요': 예/아니오/새로 로그인하지 않음

## 1. 가린 상태
- 출결상세를 열 때 나가는 요청: (주소 모양 목록)
  - 이름·전화 항목이 있는 응답: (주소 모양: 원문/가림) / 없음
- '실제 시간 기반'을 누를 때 나가는 요청: …
- JSON 항목 (isRealTime/true · false)
  - name: 원문/가림(모양)   userName: …   phone: …   identifier: …
  - attendeeId: 있음/없음 (true·false 응답에서 같음/다름)   sequence: 있음/없음
  - eventList[].userId: 있음/없음   eventList[].eventId: 있음/없음
  - eventList[].memoByAdmin: 원문/가림/일부 가림/메모 있는 학생 없음
  - 새 항목 이름: …
- 표 순번 = JSON sequence: 같음/다름 (3명 중 …명)   순번 빠진 번호: 있음/없음   표 순서 = JSON 순서: 같음/다름
- 학생 명단 표 머리글(왼쪽부터): …   표 개수: 2개/…개
- 제목 줄 담임 이름: 원문/가림   강의 목록 반 이름·날짜·담임: 그대로/바뀜(…)
- 이름 가림의 * 개수: 늘 2개/글자 수에 따라 다름
- 첫 글자 말고 보이는 글자가 있는 이름: 없음/있음(모양 …)
- 첫 글자 + 끝 4자리가 같은 학생: 있음/없음
- 날짜가 달라도 attendeeId: 같음/다름   userId: 같음/다름
- 기록 없는 학생의 attendeeId: 있음/없음/해당 학생 없음
- 1교시 수정창 #name: 원문/가림   #memoByAdmin: 원문/가림/일부 가림/메모 없음   전화번호: 보임/안 보임   변경·삭제 버튼: 보임·활성/…   열 때 브라우저 알림창: 없음/있음
- 퇴실 수정창: (같은 항목)
- 외출 창 제목의 이름: 원문/가림/외출 학생 없음
- 정상처리 창 목록: 이름 원문/가림, 구분 정보 …, 미리 체크된 학생 있음/없음
- update·delete 본문(코드): 10/14와 같음/다름(…)
- 설정 메뉴: 마스킹 관련 메뉴 이름 …/없음

## 2. 해제 상태
- 해제 창 문구: 인증번호 …자리, 유효 …분   메일 도착까지: 약 …초
- 해제 창: 화면 안의 창/브라우저 알림창   메일 계정: 연결 프로그램 계정과 같음/다름/모름
- 해제 때 나가는 요청: …   출결상세 다시 받기: 같은 주소/다른 주소(…)/안 받음/요청 없음
- JSON name·phone·identifier·memoByAdmin: 원문/가림   attendeeId·userId: 해제 전과 같음/다름
- 수정창 #name·#memoByAdmin·외출 창 제목·정상처리 목록·제목 줄 담임: 원문/가림
- 유지 범위: 새로고침 …, 다른 날짜 …, 다른 반 …, 새 탭 …
- 타이머: 연장 1번 = +…분, 끝나면 새로고침 없이 가림으로: 예/아니오
- 연장·종료·시간 끝 때 브라우저 알림창: 없음/있음(문구 모양 …)
- 해제 중 연결 프로그램 수집(사용자): 성공/실패/하지 않음
```

## 4. 끝나면 사용자에게 알릴 것

- Drive 폴더에 올린 파일 이름
- 핵심 네 줄
  1. 가린 화면의 JSON 이름·전화번호: 원문/가림
  2. attendeeId: 있음/없음, 날짜가 달라도 같음/다름
  3. 해제가 유지되는 범위(새로고침·다른 반)
  4. 관리자 메모·담임 이름이 가려지는지(가려지면 연결 프로그램이 가린 값을 체크히어에 다시 쓸 수 있어 먼저 막아야 함)
- 0번에서 반려된 요청이 있었는지, 중계를 멈췄는지
