# 체크히어 반·기간 일괄 수집 — 2026-10-13 (연결 프로그램 build 20261013.1)

## 화면

- 반: `전체 17개 반`, 한 반, 또는 `여러 반 선택…`(체크박스). 표도 고른 반만 보여 준다.
- 수집 방식
  - **빠른 수집(기본)**: 화면 표의 실제 입실·교시·퇴실·외출이 지난 완전 수집과 같으면 그 학생의 메모 창을 열지 않는다.
  - **정밀 수집**: 모든 학생의 입실·퇴실 메모 창과 외출 창을 다시 연다. 체크히어에서 메모만 직접 고친 경우가 있을 때, 보고·정산 전에 쓴다.
- 연결 프로그램이 `batch-sync-v1`을 지원하면 고른 반×기간 전체가 **연결 프로그램 안의 작업 하나**로 돈다. 화면은 진행만 지켜보고, 끝난 날짜마다 그날 전체 기록을 플랫폼 DB에 저장한다(같으면 읽기 1건, 쓰기 없음). 저장한 날짜는 브라우저에 기억해 다시 열어도 중복 확인하지 않는다.
- 끝나면 확인 필요(실패·일부 미수집)·강의 없는 날·DB 저장 실패를 따로 보여 준다.

## 연결 프로그램

- `/api/sync-batch {classIds, dates, mode}`: 반당 일정 목록을 한 번 훑어 강의가 없는 날을 바로 제외한다. 단, 목록을 끝까지 다 봤고 그 날짜가 목록의 날짜 범위 안일 때만 제외한다. 그 밖에는 기존처럼 날짜를 직접 찾는다.
- 실패했거나 일부 학생을 못 읽은 날은 끝에서 한 번 더 시도한다(빠른 수집이면 못 읽은 학생만 다시 연다).
- 로그인이 풀리면 남은 날을 모두 실패로 채우지 않고 작업을 멈춘다. `수집 중단`은 날짜 사이에서 멈춘다.
- 찾아낸 반·날짜 주소와 반 강의 주소를 `data/attendance.sqlite`의 `places`에 기억한다. 다음 수집부터 강의 목록 페이지 넘기기를 건너뛴다. 기억한 주소로 연 화면의 반·날짜가 맞지 않으면 그 주소를 버리고 한 번 다시 찾는다(검증용으로 넘겨받은 주소는 바꾸지 않는다).
- 작업 상태 저장은 2초에 한 번으로 줄였다(진행 표시는 메모리에서 바로 나간다).

## 정확성 장치(기존 유지)

반·날짜 제목 확인, 표 머리글 구조 확인, 명단·출결 행 수 일치, 전화번호 기반 학생 식별·중복 거부, 외출 횟수와 상세 구간 수 일치, 상세를 못 읽은 학생은 `일부 수집 실패`로 남기고 빈 메모로 바꾸지 않음.
