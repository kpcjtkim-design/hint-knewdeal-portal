# 2기 베타 마스터시트 설치 안내 (Cowork · 채팅 Claude용)

`/beta2`(관리자 전용 비공개 화면)는 마스터시트를 DB로 쓰고, 체크히어는 지금처럼 Firebase 저장본을 씁니다.
이 폴더의 `beta2.gs`를 마스터시트 Apps Script에 넣고 웹앱을 새 버전으로 다시 배포하면 화면이 동작합니다.
Vercel 환경변수(`HINT_SHEET_API_URL`, `HINT_SHEET_API_KEY`)는 **바꾸지 않습니다**(같은 웹앱 주소를 새 버전으로 배포).

## 설치 순서 (HINT 운영 마스터시트 (1기 데이터))

1. **백업.** 마스터시트 → 확장 프로그램 → Apps Script를 연다. 지금 있는 파일(`Code.gs`, `Sidebar.html` 등)을 그대로 복사해 저장소 `apps-script/master/`에 넣을 수 있게 사용자에게 전달한다(커밋은 사용자 확인 후).
   - `Code.gs`에 반별 출결판(3001~3017 탭)을 다시 그리는 함수가 있으면 이름을 알려 준다. `beta2.gs`에도 같은 일을 하는 `b2RefreshBoards_`가 있어, 둘 중 하나만 쓰도록 정리해야 한다.
2. **새 파일 추가.** `+` → 스크립트 → 이름 `beta2` → 이 폴더의 `beta2.gs` 내용을 통째로 붙여 넣는다.
3. **doPost 교체.** `Code.gs` 맨 아래의 2기 베타 데이터 API(`doPost`)를 저장소 `apps-script/teacher-beta-api.gs`의 최신 `doPost`로 바꾼다. 바뀐 곳은 두 줄이다.
   - 함수 표에 `B2_ACTIONS`를 합침(`Object.assign(..., typeof B2_ACTIONS === 'object' ? B2_ACTIONS : {})`)
   - Vercel이 보낸 사용자 이메일·역할을 `__ACTOR`·`__ACTOR_ROLE`에 넣음 (변경이력·서류 신청자 기록용)
4. **편집기에서 차례로 실행.** 처음 실행 때 권한 승인 창이 뜨면 hint.kpc 계정으로 승인한다(시트, Drive 읽기, 메일 보내기, 트리거).
   1. `b2Setup` — 출결원장 R~T열 머리글(출처 · 동기화 지문 · 동기화 확인)을 만든다.
   2. `b2ImportAll` — 운영총괄 17개 반을 처음으로 모두 가져온다(1~3분). 실행 로그에 `stats`가 찍힌다.
   3. `b2InstallTrigger` — 10분마다 `b2SyncTick`을 실행하도록 등록한다.
5. **웹앱 새 버전 배포.** 배포 → 배포 관리 → 기존 웹앱 연필 → 버전 `새 버전` → 배포. 실행 사용자: 나(hint.kpc), 액세스: 모든 사용자. **새 배포를 만들지 말 것**(주소가 바뀜).
6. **확인.** `https://hint-knewdealportal.vercel.app/beta2`에 관리자 계정으로 로그인 → 홈 상단 '운영총괄 확인 n분 전'이 보이고 반 카드에 숫자가 나오면 끝.

## 시트에 생기는 것

- **출결원장 R열 `출처`**: `1기 동기화`(운영총괄에서 온 행) · `베타 수정`(/beta2에서 저장) · 빈칸(직접 입력·기존 행)
- **S열 `동기화 지문`**: 동기화로 넣은 값의 지문. 사람이 고치면 지문이 달라져 다음 동기화가 그 행을 **덮어쓰지 않는다.**
- **T열 `동기화 확인`**: 베타에서 고친 행이 운영총괄과 다를 때 운영총괄 값을 적는다. 화면의 '운영총괄 값으로'를 누르면 되돌린다.
- 출결원장은 지금처럼 **출석이 아닌 날만** 한 줄씩 둔다. 베타에서 '출석'으로 바꾸면 행을 지우지 않고 유형 `출석`으로 남긴다(운영총괄 값이 다시 덮어쓰지 않게).
- 운영총괄 `중복`(목록 문구 `중복(지각+외출, 지각+조퇴, 외출+조퇴)` 포함)은 유형 `중복`으로 가져오고 T열에 '유형 확인 필요'를 적는다.
- 사유에 시간이 섞여 있으면 시트 칸으로 옮긴다: 지각 `09:14` → 입실, 조퇴 → 퇴실, 외출 `(9:00-10:00)` → 외출 시작·종료. 끝의 `(인)`·`(인정)` 표기는 지운다.
- T열 중 `운영총괄 값: …` · `운영총괄에는 …` · `같은 학생…`만 **충돌**이다. `사유: 동명이인·이름 경계 확인 필요`처럼 해석 참고 메모는 화면에 '참고'로만 보이고 '동기화 확인' 건수에 넣지 않는다.
- 증빙: 운영총괄 칸 색(노랑=확인, 빨강=반려)만 J열에 넣는다. 나머지는 O열 수식이 `미제출`/`해당없음`을 계산한다.
- 명부: **출결원장보다 먼저** 쓴다(이름 칸 데이터 확인 규칙과 맞추기 위해). 없는 학생 추가, 중도탈락(마지막 입력일 기준 해당없음 2일 이상)은 상태가 비었거나 재학일 때만 `중도탈락`으로 바꾸고 **상태 변경일 = 마지막 출석일**(2기 담임 화면 기준: 그다음 교육일부터 빠짐). 예전 beta2가 쓴 `중도포기`는 `중도탈락`으로 고친다. 생년월일·성별은 `교육생정보` 탭에서 빈 칸만 채운다.
- 반별 출결판(3001~3017)은 **Code.gs `rebuildBoard_`와 같은 표기**로 그린다: 출결원장 유형 그대로(증빙 대기 `*` 없음), 기록 없으면 `출석`, 상태 변경일 다음부터 빈칸.
- **기존 행 한 번 맞추기**: beta2 설치 전부터 있던 행(출처 빈칸 또는 `직접 입력`, 지문 빈칸)은 다음 전체 동기화 때 한 번만 운영총괄 값으로 맞춘다(사용자 결정 2026-10-13). 단, **설치일(2026-10-13) 이후 변경이력에 사람이 고친 기록이 있는 학생·날짜는 맞추지 않는다**(담임 포털·출결판·패널에서 고친 행 보호). 맞추기는 반마다 그 반을 운영총괄과 맞추는 실행 안에서만 하고(읽기 오류가 난 반은 다음에), 끝난 반은 `B2_LEGACY_DONE`에 적는다. 17개 반이 모두 끝나면 `B2_LEGACY_ADOPTED=2`가 되고, 그 뒤 출처가 빈 행·`직접 입력` 행은 덮어쓰지 않고 다르면 T열에만 적는다.
- 반정보: 빈 칸만 운영총괄 값으로 채운다. 서류발급: 운영총괄 `서류발급요청` 내역을 `1기-행번호`로 가져온다.
- 변경이력: 베타 저장은 한 줄씩, 동기화는 바뀐 것이 있을 때만 요약 한 줄.

## 효율 (트래픽·한도)

- 10분 트리거는 **평일 09:10~18:00에만** 돈다(스크립트 속성 `B2_SYNC_WINDOW`로 바꿈, 예 `1-5 08:30-18:30`, `always`). 시간 밖이면 시트를 열지 않고 바로 끝난다.
- 먼저 운영총괄 파일의 수정 시각만 본다. 바뀌지 않았으면 1초 안에 끝난다(하루 트리거 실행시간 한도 90분 대비 여유).
- 바뀌었으면 **Google Sheets API 서비스**(편집기 '서비스 +'에서 추가, 식별자 `Sheets`)로 17개 반·서류발급요청·반정보를 한 번에 읽는다(탭 이름을 먼저 확인해, 이름이 바뀐 탭이 있어도 나머지는 한 번에 읽고 그 반만 오류로 남김). 서비스가 없으면 반마다 읽는다(느림). 서비스가 일시 오류로 실패하면 10분 실행은 한 번은 반마다 읽기로 넘어가지 않고 끝내며(`B2_SYNC_LAST.apiError`) 다음 실행이 API로 다시 읽는다. 다음 실행도 실패하거나(`B2_API_FAILS`, API로 읽으면 지워짐) 일시 오류가 아니면(권한 없음·API 꺼짐 등) 반마다 읽기로 넘어가고, 전체 다시 맞추기(지금 가져오기·버전 변경)는 처음부터 넘어간다. 반마다 읽기도 반마다 남은 시간을 보고, 모자라면 아무것도 기억하지 않고 잠금 전에 멈춘다. 실행 기록 `B2_SYNC_LAST.mode`가 `api`/`sheet`.
- 반마다 값 지문(`B2_SRC_HASH`)을 남겨 **바뀐 반만** 출결원장에 반영한다. 포털에서 저장한 반(`B2_DIRTY`)과 증빙 색이 바뀐 반도 반영한다. 색은 실행마다 4반씩 돌아가며 확인하고, 운영총괄이 바뀐 뒤 한 바퀴(5번)는 파일이 그대로여도 계속 돈다.
- 출결원장은 **바뀐 행만** 고치고 새 행은 아래에 붙이며 없어진 동기화 행은 비운다(빈 행이 남음). **행 순서를 바꾸지 않는다**(예전의 '통째로 정렬해 다시 쓰기'는 없앰). 바뀌지 않은 행은 건드리지 않고, 붙어 있는 행끼리만 한 번에 쓴다. 정렬해서 보고 싶으면 필터 보기를 쓴다.
- 쓰기 순서는 끊겨도 다음 실행이 바로잡을 수 있게 정했다: 값이 바뀌는 동기화 행은 R:T를 먼저 `1기 동기화`·`*`로 표시 → A~K 값 → 마지막 R:T. 새 행은 R:T 먼저, A~K 나중.
- 쓰기 직전(일시 오류로 다시 시도할 때도 매번) 행 위치가 그사이 바뀌었는지(누가 행을 지우거나 끼워 넣거나 정렬함) 확인하고, 바뀌었으면 이번에는 쓰지 않고 다음 실행이 다시 맞춘다.
- S열(동기화 지문)은 쓰기 전에 '일반 텍스트' 서식으로 둔다. 일반 서식이면 `01234567`·`12345e67` 같은 지문(약 1.6%)이 숫자로 바뀌어 다시는 맞지 않았다(예전 코드에도 있던 문제, 다음 실행이 한 번 고쳐 씀).
- 출결판은 바뀐 반만 다시 그리고, **날이 바뀐 뒤 첫 실행에 17개 반을 모두** 다시 그린다(Code.gs `onOpen`은 더 이상 그리지 않음). 4반까지는 동기화 잠금 안에서, 나머지는 4반씩 잠금을 다시 잡아 그린다(그 사이 담임 저장이 잠금을 오래 기다리지 않게). 그릴 반은 출결원장 쓰기 전에 `B2_PENDING_BOARDS`에 적어 두어, 끊기면 다음 전체 동기화가 이어서 그리고 변경 번호도 올린다. 그리지 못한 반은 경고(`B2_SYNC_LAST.warnings`)로 남기고 3번까지 다시 시도한다(`B2_BOARD_FAILS`). 한 반 가져오기(`b2SyncNow`)는 그 반 출결판만 그리고, 그리지 못하면 남은 출결판에 더해 다음 전체 동기화가 그린다. 출결원장 반영이 끝난 뒤 출결판을 그리다 생긴 오류(잠금 대기 초과 등)는 실행 오류가 아니라 경고로 남는다.
- 시트 일시 오류(`Service Spreadsheets failed while accessing document` 등)는 2초·6초 쉬고 다시 시도한다. 'timed out'으로 끝난 호출, 남은 실행 시간이 쉬는 시간+그 시도 시간보다 적을 때, 증빙 색 읽기는 다시 시도하지 않는다(색 읽기가 한 번 실패하면 그 실행의 돌아가는 색 확인은 멈추고, 다음 실행은 실패한 반 다음 반부터 잇는다. 실패한 반은 다음 바퀴에 다시 본다. 계속 실패하는 탭이 돌기를 막지 않게). 시트 쓰기는 모두 문서 잠금 안에서 한다. 다시 시도한 기록은 `B2_SYNC_LAST.retries`, 단계별 시간은 `B2_SYNC_LAST.t`(ms).
- 시트 시간대는 실행마다 한 번만 묻는다(예전에는 날짜 칸마다 물어 10분 실행 한 번에 1만 번 넘게 불렀다). 날짜·시간 글자도 실행 안에서 같은 값은 한 번만 바꾼다(`b2Fmt_`, Code.gs `fmtDate_`: 원장 행마다 부르던 `Utilities.formatDate`가 서로 다른 날짜·시간 수백 번으로). 동기화는 출결원장 A~K·R~T만 읽고 L~Q 수식 열은 읽지 않는다(포털 화면 읽기 `b2Bundle`은 그대로 전부 읽음).
- 실행 시간: 단계마다 `B2_SYNC_PHASE`(`{phase, at, ms}`, 단계 start·drive·days·source·colours·lock·read·write·slim(시트 다듬기 뒤 Q 계산)·boards n·done)를 남기고 남은 시간(`B2.SYNC.runMs` 5분 기준)을 본다. 모자라면 쓰기 전에 스스로 멈추고(`B2_SYNC_LAST.late`에 멈춘 단계, 지문·수정 시각은 기억하지 않아 다음 실행이 다시 맞춤), 출결판은 남은 반을 `B2_PENDING_BOARDS`에 두고 멈춘다.
- 하루 트리거 사용 시간(`B2_RUN_USAGE`)이 60분을 넘으면 30분에 한 번만 돈다. 6분 한도로 끊긴 실행은 다음 실행이 `B2_SYNC_CUT`(`{at, phase, ms}`, 마지막 단계)에 남기고 하루 사용량·마지막 실행 시각에 넣어 바로 저장하며(그 실행도 끊겨도 쌓임), /beta2 상태 표시에 '시간 초과 중단'과 멈춘 단계로 보인다.
- 명부도 출결원장과 함께 쓰기 직전 시간 확인 뒤에 쓴다(시간이 모자라 멈춘 실행은 명부·출결원장 어느 것도 쓰지 않음). 명부를 쓰기 전 이름 칸으로 행이 그사이 밀렸는지 확인하고, 밀렸으면 쓰지 않고 멈춘다(다음 실행이 다시 맞춤).
- '운영총괄 값으로'(`b2Release`)는 그 반을 `B2_DIRTY`에 넣어, 뒤따르는 한 반 동기화가 시간이 모자라 멈춰도 다음 10분 실행이 그 행에 운영총괄 값을 넣는다.
- 화면은 반 하나 또는 전체를 한 번에 읽고(`b2Bundle`), 30초마다 변경 번호(`b2Rev`)만 확인한다. 번호가 같으면 다시 읽지 않는다.
- `b2Bundle`은 시트를 한 번 읽을 때 17개 반·전체용 조각을 **스크립트 캐시(6시간)**에 넣고, 다음 호출은 시트를 읽지 않는다. 캐시 표시는 캐시 형식 번호(`B2_CACHE.v`, 조각 모양을 바꾸면 올림) + `B2_REV` + 마스터 파일 Drive 수정 시각이라, 어느 경로로 고쳐도(직접 편집·다른 스크립트 포함) 다음 호출이 다시 읽는다. 다만 Drive 수정 시각은 조금 늦게 바뀔 수 있고, 행 삭제·끼워 넣기·정렬은 onEdit이 없어 `B2_REV`가 오르지 않으므로 열린 화면은 다음 변경 번호가 오르거나 새로 열 때 바뀐다. 변경 번호가 오른 뒤 여러 화면이 함께 부르면 한 실행만 시트를 읽어 캐시를 채우고(스크립트 잠금) 나머지는 그 캐시를 쓴다. `rev`·`today`·`sync`는 호출마다 새로 붙고, 스크립트 속성은 한 번에 읽는다(`b2Rev`·`b2Bundle`·`b2Status`, 하루 속성 읽기 한도). 캐시 오류·조각 없음은 그냥 시트를 읽는다. `Code.gs`도 출결원장·명부·교육일자·반정보·시간표를 쓰면(`upsert_`·`removeRow_`·`portalSetStatus`·`onEdit` 직접 편집) `B2_REV`를 올려 열린 화면이 바로 다시 읽는다(beta2.gs가 없으면 아무것도 안 함. 저장은 Q를 쓴 뒤에 올림). 새 권한은 필요 없다(CacheService, 이미 쓰는 Drive 읽기).
- 저장은 시트에 한 행만 쓰고, 화면은 받은 값으로 그 행만 고친다.
- 체크히어는 오늘 날짜만 문서 1개를 실시간 구독하고, 지난 날짜는 한 번만 읽는다. Firebase 쓰기는 체크히어 수정 요청뿐이다.

**문제.** 배포 ①·② 모두 `doGet`으로 담임 포털(Portal.html)을 열고, 소유자(hint.kpc)로 실행된다. 그 화면에서는 이름 끝이 `_`가 아닌 **모든 최상위 함수**(Code.gs·beta2.gs 전부)를 누구나 `google.script.run`으로 키·PIN 없이 부를 수 있었다. 예: `portalRoster`(생년월일·성별), `b2Docs`(역할이 비어 생년월일까지 보냄), `b2Bundle`(모든 반 명부·출결), `saveRecord`·`b2Save`(아무 반 출결 쓰기), `setApiKey`(키를 바꿔 Vercel 연결 끊기), `b2SyncTick`·`b2SyncNow`(동기화를 계속 돌려 잠금·하루 한도 차지).

**바뀐 것**
- Vercel 전용 함수는 이름 끝에 `_`를 붙였다: `portalRoster_`, `b2Bundle_`·`b2Rev_`·`b2Status_`·`b2SyncNow_`·`b2Save_`·`b2Release_`·`b2Docs_`·`b2DocCreate_`·`b2DocUpdate_`. `doPost` 함수표와 `B2_ACTIONS`의 **동작 이름은 그대로**라 Vercel(`api/teacher-beta.js`)·환경변수는 바꾸지 않는다.
- 편집기·메뉴·패널 전용은 첫 줄에서 부른 사람과 실행 계정이 같은지 본다(Code.gs `editorOnly_`, beta2 `b2EditorOnly_`와 같은 판단): `saveRecord`(출결 입력 패널 저장), `rebuildAll`(메뉴 '출결판 새로고침'), `setApiKey`. `onEdit`은 `rebuildAll` 대신 `rebuildBoards_`를 바로 부른다(단순 트리거는 이메일이 빈 칸일 수 있음).
- `b2SyncTick(e)`는 시간 트리거 이벤트의 `triggerUid`가 이 프로젝트 트리거이거나 편집기에서 직접 실행할 때만 돈다(`b2TriggerOnly_`). 시간대 밖이면 확인 전에 그냥 끝난다.
- 그대로 둔 것: Portal.html이 부르는 `portalClasses`(반 이름·PIN 유무만)와 PIN을 확인하는 `portal*` 8개, 패널이 0.7초마다 부르는 읽기 `getContext`·`getSelectionKey`(웹 앱에서는 고른 칸이 없어 안내 문구만), 메뉴 함수(웹 앱에는 화면이 없음), `doGet`·`doPost`(API 키).
- 붙여 넣기용 사본 `apps-script/teacher-beta-api.gs`도 같이 고쳤다. 새 권한 승인은 없다(이미 쓰는 이메일·트리거 권한).
- 시험: `checkhere/tests/script-run-guard.test.mjs`. `_` 없는 함수 목록이 바뀌면 실패하므로, 함수를 더하면 그 시험의 분류 표에 넣고 웹 앱 방문자가 불러도 되는지 정한다.

**반영 순서 (Cowork 또는 사용자)**
1. 편집기에서 `Code.gs`·`beta2` 내용을 저장소 파일로 통째로 바꾸고 저장한다. 프로젝트에 다른 `.gs` 파일이 있으면 이름을 알린다(그 파일의 `_` 없는 함수도 같은 방식으로 열려 있다).
2. **배포 ①과 배포 ② 둘 다 새 버전으로 업데이트한다**(배포 관리 → 연필 → 버전 '새 버전'. 새 배포를 만들지 않음, 주소 그대로). 버전을 고정한 배포는 예전 코드를 계속 쓰므로, 한쪽이라도 그대로면 그 주소의 포털 화면에서 예전 함수가 계속 불린다(지금 ②는 버전 5라 `saveRecord`·`setApiKey`가 열려 있다). 다른 활성 웹 앱 배포가 있으면 알린다.
3. 확인(값만, 학생 이름 없이): /beta2 홈 숫자가 나온다 · 담임 포털(② 주소)에 반·PIN으로 들어가진다 · 시트 메뉴 '출결판 새로고침'이 돈다 · 다음 `b2SyncTick` 트리거 실행이 실행 기록에서 '완료'다. 트리거가 '편집기에서 직접 실행할 때만…'으로 실패하면 트리거 확인이 실제 환경과 다른 것이니 바로 알린다(그동안 동기화가 멈춤).
